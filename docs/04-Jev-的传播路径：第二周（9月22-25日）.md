## 二、传播路径分析

### A. 第二周的传播新增了什么？

第一周 03 篇已经说过，主线是"美国英语圈 → 中文圈"两个圈层之间的二传 + 二次起跳（Laya）。第二周的链路是四个完全新增的维度：

**1. 评测战**——从 self-eval 走向 public-eval
- 9/15-19：TypeSafe 自己 `workflow evals`（711 case，对照 GPT-6 Astra + Fable 5.1 平均分）
- 9/19-21：OpenChamber 的 12,759 条推文分析 + OmniJev 的 119 条 awesome list（都是 user-generated）
- 9/21-22：JevBench v1（fstandhartinger，220 hard decisions / 534 decisions per system）——**第一次有了公开 benchmark**
- 9/22-25：BenchmarkHeaven 公布 JevBench 9/19 实测 + HuggingNews 给出几何均值打分（Jev 75.3 第一名）
- **变化**：从"自家报告"到"公开榜单"是质变。这让 Vercel 13% 等使用侧数据有了独立的"准确度对照系"

**2. 开源复刻战**——从 awesome list 走向 stars 排行榜
- 9/19-21：OmniJev 119 条目 + Laya / Kev 等 5-6 个仓库
- 9/22-25：Laya 19,301 stars（Apache-2.0）+ Kev 5,385 stars + intikhab49/open-jev 等 **150M 参数 30 分钟可训练**的复刻
- **关键变化**：从"有 awesome list"到"有 Apache-2.0 top-level 项目"——后者意味着真正进入 GitHub trending 的可见带

**3. 平台合作落地**——从"24h 接入"到"周级案例"
- 9/17：Vercel + Cloudflare + LangChain + Langfuse 四家同时接入
- 9/21：LangSmith Evals 把 Jev 作为 judge
- 9/22：MotherDuck `prompt_jev()` SQL 函数——**Jev 第一次有了"周级完整 case study + 公开复现指令"**
- **变化**：从"接入列表"到"完整 SQL 扩展"是工程落地深度跨越

**4. 二次稀缺感反转**——一个罕见的产品策略组合
- 9/15-19：waitlist 创造开局稀缺感
- 9/20：waitlist 取消 + $5 注册金
- 9/22：暂停新 signups
- 9/25：Vercel free window 结束
- **变化**：用"5 天稀缺 → 2 天充分 → 暂停注册 → 第三方便宜窗口关闭"四步策略**让稀缺感在不同时点重新出现**，每一次都给传播创造新的"窗口期"

## 三、机制分析（回答「为什么」，不只描述）

### 1. 「独立评测出现」是话题产品 → 基础设施的拐点信号

第一周 03 篇第七节已经分析过 Vercel AI Gateway 13% / Jevable 194 项目 / 独立 dev 案例构成的"**使用侧写**"——但这些使用侧写**没有公开评测来交叉验证**。一个产品"被使用"和"被验证"是两件事：Jev 在第一周被使用但没有被独立验证。

9/22 MotherDuck `prompt_jev()` + 9/19 JevBench v1 + 9/24 OrcaRouter 质疑这三件事组合起来，才让 Jev 第一次有了"使用侧写 + 验证侧写并行"的格局。这是个**有质感的拐点**——意味着 Jev 的**讨论语义**从"这个模型到底是不是真的"变成"这个模型在不同评测集上的相对位置"。

**机制结论**：独立评测出现 = 把"质疑文化"装回产品自身。第一周靠"营销数字自我升级"撑过"用者自报"的脆弱性，第二周公开评测 + 第三方质疑把"质疑"从社区外搬回产品内——这是健康的扩散模型，不是失控。

### 2. 「开源复刻战」让护城河从产品体验变成 API 形态

Laya 19k stars / Kev 5.4k stars / intikhab49 150M 30 分钟复刻——这三件事一起传达了一个信号：**Jev 的算法并不稀有，稀有的是 TypeSafe 把这个 API 形态打磨得能用的工程能力**。

注意一个细节：
- intikhab49 的复刻 0.697 accuracy vs Jev 0.727（低 4%）
- intikhab49 自称 "2.5x better calibrated, 4x faster"
- **TypeSafe 的护城河不是准确性，而是：用 SDK 的舒服程度 / 文档 / 控制台 / 三家网关（Vercel / Cloudflare / OpenRouter）/ LangChain 集成 / Langfuse 集成 / LangSmith Evals 集成——这一整套产品表面的工程能力**

**机制结论**：开源复刻战让 Jev 的"独家性"从"我有一个新模型"变成"我有这套 API + 集成"。前者两周就被复刻完，后者需要半年到一年才能追上——这正是为什么 TypeSafe 在 9/22 暂停注册：**让更多人来用他们打磨好的工程能力，而不是来调他们没打磨好的模型**。

### 3. 「二次稀缺感反转」是比单次稀缺感高一个数量级的策略

传统产品发布要么"全程 waitlist"（缺），要么"全程开放"（不缺）——TypeSafe 的做法是**分段切换**：

| 窗口（相对发布） | 状态 | 传播目的 |
|---|---|---|
| D+0~5（9/15-19） | waitlist | 创造稀缺感 → 媒体放大 + Tier 1 开发者试用 |
| D+5~7（9/20-22） | 开放 + $5 注册金 | 流量转化 → 大量注册 + 使用侧写 |
| D+7（9/22） | 暂停 signups | 紧迫感 → "注册不上了"的反向传播 |
| D+10（9/25） | Vercel free window 关闭 | 最后一波免费机会 → 引流第二周末尾 |

**这四个窗口**给传播持续供给"窗口期"。每一窗口结束，下一窗口开始——这是**用产品供给曲线来设计传播节奏**，而不是单点造浪。

**机制结论**：稀缺感的真正价值在于**"从有到无"这一刻**，而不是"长时间没有"。TypeSafe 在第一周造"从无到有"，第二周造"从少到无"——两次切换，传播力最强。

### 4. 评测方法学之争是 Jev 第一次被认真对待

CellCog 9/19 是描述性 / 解释性的；JevBench v1 + OrcaRouter 9/24 是真正的质疑。质疑点："**Jev 是被 GPT-6 Astra + Fable 5.1 的平均分评估的，而 GPT-6 Astra 又是 Jev 直接的对手**"。

这不是技术细节——这是个**生产链信任问题**：评估一个人靠"另一个人说"，而另一个人恰好是这个人的对手。

**但是** TypeSafe 自己已经定下了不回公开 benchmark leaderboard 的策略（explainx 9/24 文里 Alan 团队的回应）。所以这个争议**不会在评测场上被解决**，会在产品形态上被解决——也就是说，TypeSafe 的下一步可能就是：

- 开放 Jev 自己的 ground-truth 数据集
- 或者和 Anthropic / OpenAI 公开 audit benchmark
- 或者不再发布"对标 LLM"的工作流评测

**机制结论**：争议不会消失，但方法学会被推动透明化。这是 Jev 第一周的"营销数字不可质疑"已经走完的标志——**第二周开始质疑文化回到它应有的位置**。

## 四、反思：第二周我看到的几个东西

### 1. 第一周的传播结构并没有被推翻，而是被撑开了

03 篇第七节提到的"传播学最优结构"在第二周仍然成立。变化是**这个结构本身开始生产新的结构**——评测战 / 复刻战 / 平台落地 / 二次稀缺感四个新维度，都是第一周那 9 个传播节点（Diogo thread / 官方博客 / LangChain 集成 / ...）自然延展出来的。

第一周给了"产品能不能传出去"的答案，第二周给了"传出去之后能不能留下来"的答案——后者比前者难得多。

### 2. 中文圈的"水位"似乎到了

第一周 Tony Bai 那一篇（13 分钟阅读）作为中文圈第一篇 KOL 长文**触发了水位**。第二周像 `NanmiCoder/jev-arena` 这样的"独立工具型二次创作"出现，但 KOL 级长文没有继续产生。

可能原因（基于个人推测，无 evidence）：
- 话题爆点在 9/20 已经过
- 中文圈对"decision model"这个抽象品类的接受速度比英文圈慢
- 中文圈更看重"商业落地案例"，而 MotherDuck SQL 扩展这种工程深度案例第一周就是英文圈的

**如果中文圈不能在第三周出现 KOL 长文 + 独立工程落地案例，水位可能在 9/20 后就开始退潮**。这是观察点。

### 3. 一个产品最难的阶段不是 0 → 1，是 1 → 100

第一周解决"0 → 1"（这个模型是什么）—— 信息差 + 数字差。  
第二周开始"1 → 100"（谁在用，用得怎么样）—— 工程差 + 数据差。

第二周出现的 JevBench / OrcaRouter / intikhab49 复刻 / Laya 19k stars **全部**是为"1 → 100"铺路的——他们讨论的不再是"模型能不能用"，而是"模型有什么不能用"。

TypeSafe 的核心策略在过去两周看起来一直是：**用产品形态的工程密度，去换用户对模型准确性的疑问**。这是少见的产品哲学——大多数模型厂商反过来用数据密度去换用户对工程形态的疑问。

### 4. 留给自己的问题

- JevBench 在 9/25 之后的版本迭代速度会是什么样？如果 TypeSafe 自己保持公开实测节奏（而非依赖 fstandhartinger 这种第三方维护者），JevBench v2 何时出？
- `awesome-jev-zh` 这种"中文精选 + 每日自动收录" 的运营模式会不会跑出第三个 awesome list 之外的赢家？yzfly 一家独大还是会被中文社区整合？
- 当 Vercel free window 结束（9/25），13% 付费团队的留存率是多少？这才是真正决定 Jev 是否成为"基础设施"的数字。
